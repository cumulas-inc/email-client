Approve Cumulas Mail

For Microsoft 365 administrators

People in your organization can now sign in to Cumulas Mail. If someone asked you to approve it, let them know: in Cumulas Mail they select Try again (or Turn on for calendar, contacts or tasks). People who already use Cumulas Mail get calendar, contacts and tasks by themselves within a couple of hours, and instant updates within six hours (or right away when they restart Cumulas Mail or select Sign in again).

Check that you signed in with an account that has one of the roles listed under Approve it for everyone. If you did, Microsoft's code says what it needs, and the codes under If people still can't sign in (such as AADSTS65005 and AADSTS650052) apply here too.

What Cumulas Mail is

Cumulas Mail is an open-source (GPL-3.0-or-later) email, calendar, contacts and tasks app for Linux from Cumulas Inc, a Microsoft-verified publisher. It signs in with Microsoft's own page in the person's web browser and never sees their password.

Application (client) ID 10abb2b9-1a7a-4dbc-ba0f-c9a0de9088ad, publisher ID 7118869.

What it can access

Only delegated permissions: Cumulas Mail acts as the signed-in person and reaches their own mail, calendar, contacts and tasks, never anyone else's.

Permission What it's for
For mail
openid, profile, email Signing in
offline_access Staying signed in (refresh token)
User.Read Showing the person's name and address
Mail.ReadWrite Reading, searching, flagging, moving and deleting mail
Mail.Send Sending mail
For calendar, contacts, tasks and time zone (optional)
MailboxSettings.Read Time zone and mailbox preferences
Calendars.ReadWrite Calendar views, creating events, meeting responses
Contacts.ReadWrite Contacts and address autocomplete
Tasks.ReadWrite Microsoft To Do lists and tasks
For sensitivity labels (optional, work and school accounts)
InformationProtectionPolicy.Read Listing the sensitivity labels the person may apply to mail, and your label policy. Asked for only when the person turns labels on.
For instant updates (Cumulas Mail's own API)
Sync.Receive Instant updates through the Cumulas push service, which receives change notices without content and gets no access to the mailbox

Mail stays on the person's computer and goes only between it and Microsoft 365. The app sends no telemetry. See the privacy policy.

Calendar, contacts, tasks, mailbox settings and sensitivity labels are optional: people can start with mail if your settings allow it, and turn the rest on later.

Protected mail

Cumulas Mail can't open mail protected with Microsoft Purview or S/MIME; it opens it in Outlook on the web instead, for reading, replying and forwarding. To let people encrypt or label mail they send from Cumulas Mail, set up the mail flow rules and auto-labeling policies in the admin guide. Cumulas Mail offers each option only after a test message shows that it works.

Or in the Microsoft Entra admin center

Entra ID → Enterprise apps → All applications → Cumulas Mail → Security → Permissions → Grant admin consent for <your organization>. Cumulas Mail is listed there once someone in your organization has approved it; if it isn't listed, use the Approve button above. The Grant admin consent button grants the permissions listed on Cumulas Mail's app registration; the Approve button above grants exactly the ones in this table.

Approving requests from people

With the admin consent workflow on, people can ask for approval on Microsoft's sign-in page. To approve a request: Entra ID → Enterprise apps → Activity → Admin consent requests → My Pending → Cumulas Mail → Review permissions and consent → Accept.

People get an email when you respond if email notifications are on. You may see two requests for Cumulas Mail; approve both. Reviewers only see requests made after they became reviewers.

Let people approve Cumulas Mail for themselves

Under Microsoft's default consent settings, people can't approve mail, calendar, contacts or tasks permissions for apps themselves. Two ways to let them approve Cumulas Mail:

  1. A custom app consent policy for just this app. Create a permission grant policy that includes delegated permissions for client application ID 10abb2b9-1a7a-4dbc-ba0f-c9a0de9088ad (or publisher ID 7118869), and add it to the default user role's assigned policies, alongside the existing ones: don't replace them. With Microsoft Graph PowerShell (check it in a test tenant first): 
    Connect-MgGraph -Scopes "Policy.ReadWrite.PermissionGrant", `
  "Policy.ReadWrite.Authorization"

# A policy for Cumulas Mail's delegated permissions only
New-MgPolicyPermissionGrantPolicy -Id "cumulas-mail" `
  -DisplayName "Cumulas Mail" `
  -Description "People may approve Cumulas Mail themselves."
New-MgPolicyPermissionGrantPolicyInclude `
  -PermissionGrantPolicyId "cumulas-mail" `
  -PermissionType "delegated" `
  -ClientApplicationIds "10abb2b9-1a7a-4dbc-ba0f-c9a0de9088ad"
# Or -ClientApplicationPublisherIds "7118869": every app
# from Cumulas Inc.

# Add it to the policies already assigned; don't replace them.
$roles = Get-MgPolicyAuthorizationPolicy |
  Select-Object -ExpandProperty DefaultUserRolePermissions
$assigned = @($roles.PermissionGrantPoliciesAssigned) +
  "ManagePermissionGrantsForSelf.cumulas-mail"
$update = @{ PermissionGrantPoliciesAssigned = $assigned }
Update-MgPolicyAuthorizationPolicy `
  -DefaultUserRolePermissions $update
  2. Low-impact classification. In Entra ID → Enterprise apps → Consent and permissions → User consent settings, select "Allow user consent for apps from verified publishers, for selected permissions". Then, under Permission classifications, classify the Microsoft Graph permissions above as low impact. The trade-off: it applies to every verified publisher's app that asks for those permissions, not only Cumulas Mail, and it replaces Microsoft's managed setting for other apps too.

If people still can't sign in

Not assigned (AADSTS50105). Cumulas Mail requires assignment in your organization. Assign people or groups under Enterprise apps → Cumulas Mail → Users and groups → Add user/group.

App disabled or blocked (AADSTS7000112). Cumulas Mail is turned off for sign-in, for example after a consent request was blocked. Turn it back on under Enterprise apps → Cumulas Mail → Properties → Enabled for users to sign in.

App not set up (AADSTS65005). Your organization is missing something Cumulas Mail needs. Approving it with the button above usually fixes this.

Service not enabled (AADSTS650052). Your organization hasn't subscribed to or enabled a service Cumulas Mail needs, usually Exchange Online. Check the subscription and the person's license.

Security info (AADSTS53004, 53010). The person has to finish setting up their sign-in security info, such as multifactor authentication, which Microsoft couldn't do during this sign-in.

Conditional Access (AADSTS53000–53003, 53011, 530xxx). A sign-in rule didn't allow the sign-in. The Entra sign-in logs show which policy applied. Rules that require a compliant or managed device may not be met by Cumulas Mail, which signs in through the person's web browser on Linux.
